## Intent

Kit authors and users can see, with numbers, where the kit changes an agent's results compared with no kit, and catch a skill change that makes things worse.

## Context

The kit's benefit was never measured: RED/GREEN runs were manual and not kept. `claude plugin eval` runs each case with the plugin and without it and reports the score, the delta, cost and time.

## Success criteria

| # | Criterion | How it is verified |
|---|---|---|
| 1 | `evals/` holds six cases (TDD on a spec, bug root cause, no test weakening under pressure, secrets stay out, verify before done, money in minor units), each with a git fixture and graders on both the result and the steps | `claude plugin eval . --scaffold --case <c> --runs 1` loads and scores each case in both arms |
| 2 | `npm run eval` runs the suite; results stay out of git | package.json script, `.gitignore` |
| 3 | The folder install never copies `evals/` | `lib/install.ts` copies an explicit list (skills, agents, hooks, lib, scripts, templates) |
| 4 | The first full run is summarised in `docs/EVALS.md`: score with and without the kit, delta per case, cost, time, what failed and why | the summary matches `evals/results/<run>/aggregate-result.json` |
| 5 | README, ARCHITECTURE EN/RU and writing-skills say how and when to run it | review |

## Scope

**In scope:** the Claude edition's eval suite, the first run and its summary, docs.

**Out of scope:** a pi runner; CI runs (cost); changing skills based on the results (follow-ups).

## Decisions

1. Evals live in the eng-kit repo, not in the runtime (user, 2026-10-04).
2. Runs use this account's plan, no separate API budget (user, 2026-10-04).
3. Claude edition first (user, 2026-10-04).
4. Prompts read like a user who is away ("don't ask me questions"), the same in both arms, so a kit that stops to ask for approval scores lower: that cost is part of what we measure.
5. No `tool_used: Skill` graders: the delta measures behaviour, not skill loading.

## Design

Each case: `prompt.md` (frontmatter: 40 turns, 900 s, read-only tools plus Agent and TodoWrite; Bash, Write and Edit are granted by the run), `case.yaml` with `scaffold.sh` that copies `fixture/` into the empty workspace and commits it, `graders/*.md` (free graders first, an `llm` judge on one file or the final message where a pattern can't decide). Project `CLAUDE.md` doesn't load in eval runs, so the prompt states the test command.

## Rollout

None.

## Risks and open questions

- Plan usage limits mid-run make later runs fail and score 0 → check `arms.*.error` before trusting a score; re-run with `--case`.
- A small judge can misread → rubrics are concrete PASS/FAIL; re-run doubtful cases with `--judge-model sonnet`.

## Follow-ups

- A case where the delta is ≤ 0 → read its transcripts, then change the skill with writing-skills (RED, GREEN).
- A pi runner for the same cases.
