# Review gate

The guard denies opening or merging a PR/MR, merging into the base branch and pushing to it unless the kit reviewer's last verdict is `Yes` for the commit being landed. The hook records the verdict from the reviewer's own `Reviewed HEAD:` and `Ready to merge:` lines when the reviewer finishes; you never write it yourself.

- **A verdict covers exactly the commit the reviewer reviewed** (its `Reviewed HEAD`). Any change after it needs a new review: a new commit, an amend, a rebase onto a newer base, a docs edit, deleting the task file. A branch that changes only documentation is reviewed the same way. So review last: after docs, the task-file removal and any rebase. Commits already on the remote base land nothing new and need no review.
- Land in a command of its own: a landing chained after anything but read-only steps (`cd`, `git status`/`diff`/`log`/`add`/`fetch`, `cat`, `grep`…) and the project's verification commands is refused, because the guard can't see the commit it would land. A `cd` the guard can't follow (a variable, `$(…)`, a nested subshell, a missing folder; a `cd` inside one `( … )` is followed and ends with it) or `-R` to another repository is refused too. `gh pr merge <number>` asks, because the PR's head isn't known locally; name the branch, or merge from it (the remote branch is checked as well).
- If the reviewer's report lacks the two verdict lines, the hook sends it back once to add them; a second miss counts the run as failed: `Inconclusive` for the commit it reviewed, within that prompt. A review of a later commit is unaffected.
- A review counts only for verified code: one that ran while edits were unverified (the verify gate wasn't green) is recorded as `Inconclusive`. Run the checks first, then review.
- `With fixes`, `No` and `Inconclusive` all block: fix, then re-review the new range.
- Parallel reviewers dispatched for one user prompt combine to the worst verdict. A finding you pushed back on without changing code is withdrawn by a re-review in a later prompt, after the user has seen your reasoning.
- Only the user can waive the gate (`"reviewGate": false` in `.claude/guard.json`, whose edits the guard asks about). A self-review in a separate pass does not satisfy the gate.
